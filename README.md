# TempusAct

安卓本地循环计时器，原名“健身钟”，面向个人或少数人安装 APK 使用，重点验收设备为小米 15。1.1.0 更名为 TempusAct，沿用原应用标识和签名，可覆盖升级并保留方案与历史。

## 安装与使用

从 [v1.1.0 发布页面](https://github.com/Evergarden666/TempusAct/releases/tag/v1.1.0) 下载 APK，将它传到手机，在文件管理器中打开并按系统提示安装；已安装相同签名的旧版时可以直接覆盖安装。最低支持 Android 8.0（API 26），目标版本为 API 36。

自行构建后，安装包位于 `artifacts/TempusAct-1.1.0.apk`，校验和位于相邻 `.sha256` 文件。`artifacts/` 是本地产物目录，不随源码上传，首次克隆时不存在。

1. 首次打开创建一套方案：填写方案名称、事件名称和各自的分秒时长，按需要添加、移除或调整事件顺序。
2. 设置默认循环次数、准备秒数，以及提示音和震动开关，选择“保存”或“保存并开始”。准备默认 5 秒，填 0 关闭。
3. 后续从“我的方案”选择即可开始；“本次循环次数”只影响本次，不修改已保存方案。
4. 计时页突出当前事件与大数字倒计时，显示轮次、下一事件和本次剩余时间。支持暂停、继续、结束、重新开始。
5. “历史记录”默认按使用的循环方案自动分组，显示组内记录数及实际总用时；进入组可查看各次记录，也可切换到全部记录。
6. 在记录详情中删除单条记录，或在列表选择多条记录批量删除。删除前需要确认，删除后组内总用时立即更新；循环方案保持不变。

分组按方案的唯一标识区分，同名方案不会混在一起，同一方案改名后产生的记录仍属于同组。组名取最近一次记录中的方案名称；详情始终保留使用时的设置。删除方案后，它过去的记录及分组仍然保留；组内最后一条记录删除后，该组不再显示。

组内总用时累加每条已结束记录的实际事件计时，包括提前结束时已经计时的部分，排除准备、暂停和中断等待。待恢复记录可以查看，需先继续或结束本次计时再删除；它不计入已结束记录的组汇总。

实际计时包含全部事件（包括休息），排除开始前准备、暂停和中断等待。提前结束会保存已经计时的部分；仅准备阶段取消不生成历史。“重新开始”和“再来一次”沿用本次轮数，创建新会话并重新准备。

异常中断后打开应用，会停在“等待恢复”，由用户继续、结束或重新开始；已有事件计时的中断会话也显示在历史中。恢复使用最近保存的进度，正常检查点间隔约 1 秒，不将无法确认的中断时间补入记录。

方案、历史和恢复进度只保存在本机；无需登录，不申请网络权限，没有导出、导入或云同步功能。卸载应用或清除应用数据会删除本地记录。

## 小米 15 使用与验收

首次开始时建议允许通知，以便通过锁屏通知暂停或继续。应用前台运行时保持常亮；手动锁屏或切到其他应用后使用前台服务继续计时。

首页“后台计时设置”可进入系统设置。长时间锁屏使用前，检查系统对 TempusAct 的后台运行和省电限制；具体入口名称随 HyperOS 版本变化。提示音使用闹钟音量，请在手机上确认音量和勿扰设置的实际效果。

下一事件边界使用精确闹钟唤醒，运行时系统可能显示闹钟图标。Android 13 及以上声明计时器适用的 `USE_EXACT_ALARM`；Android 12/12L 若未允许“闹钟和提醒”访问，应用仍能启动，但锁屏精确提醒需要开启该访问后验收。

1.1.0 已覆盖安装到小米 15，手机报告 Android 17（API 37）、HyperOS 4。升级后核对了原有方案和历史，均保留；已确认按方案分组、删除后总用时更新，以及键盘弹出时保存按钮的布局。17 项真实 SQLite 存储、删除与迁移测试全部通过。声音、震动及长时间锁屏提醒仍需实际使用验证，具体状态见 [TESTING.md](TESTING.md)。

## 构建

需要 JDK 17、Android SDK Platform 36、Build Tools 36.0.0。可设置 `ANDROID_HOME`，或在 `local.properties` 指定 SDK。Gradle Wrapper 固定为 9.1.0；构建使用 AGP 9.0.1、Kotlin 2.3.20 和 Jetpack Compose。

在项目根目录的 PowerShell 执行：

```powershell
.\scripts\build.ps1 -Tasks testDebugUnitTest,assembleRelease,assembleDebugAndroidTest,lintDebug
```

依赖缓存齐全时可加 `-Offline`。默认不传 `-Tasks` 时运行单元测试并生成 release APK。脚本复制 APK、SHA-256、单元测试报告和 lint 报告到 `artifacts`。

脚本优先使用本机已有的 Gradle 9.1.0，否则使用项目 Wrapper。Windows 下将 Gradle 缓存与 app 构建输出分别放在 `%TEMP%/jianshen-clock-gradle-home`、`%TEMP%/jianshen-clock-app-build`，解决 Java 17 在部分中文 Windows 环境中以系统编码读取 Gradle UTF-8 参数文件，导致中文类路径无法加载的问题。输出路径也可通过 Gradle 属性 `-Pclock.buildDir=...` 指定。

源码仓库不包含发布签名。首次克隆后运行构建脚本，会生成新的本地签名，与发布页面 APK 的签名不同，因此自行构建的 APK 不能直接覆盖安装发布版本。

维护者打包更新版本前，应私下恢复原有 `.private/clock-release.p12` 和 `signing.properties`，并沿用应用标识 `com.jianshen.clock`，这样才能覆盖升级并保留手机上的方案和历史。请私密备份这两个文件；不要发给 APK 使用者或提交到公共仓库，它们已加入 `.gitignore`。脚本发现已有密钥而缺少配置时会停止，避免替换升级所需的签名。

## 实现结构

- `core`：纯 Kotlin 时间状态机和事件提醒去重；用单调时间累计，延迟刷新可以跨过多个事件，结束时不多计时间。
- `ClockController`：串行处理开始、暂停、恢复、重置和历史写入。
- `TimerService`：前台通知、边界闹钟、声音、震动与运行唤醒锁。
- `data`：SQLite 保存方案、当前会话和历史；终止记录与当前会话清理在一个事务中完成。
- `ui`：Compose 方案列表、编辑、计时、完成及历史页面。

精确闹钟和后台策略参考 Android 官方的[闹钟文档](https://developer.android.com/develop/background-work/services/alarms)与 [Doze 文档](https://developer.android.com/training/monitoring-device-state/doze-standby)。
